# 错误处理模型

[English](errors.md) | 中文

> 本文定义 ambery 的两层错误模型——**错误层**（什么会失败、其性质）与**展示层**（每个错误在何处呈现）。不定义当前实现、协议或配置结构。

## 两层

```
   错误层                    展示层
 （来源 × 性质）            （用户在哪里看到）
                        ──►
    事件 / 状态                气泡 / banner / Card
```

## 错误层

每个错误来源都有**性质**：

- **事件**——一次性发生（本轮调用失败）。取走即清。
- **状态**——持续存在（active provider 损坏）。持续到条件修复。

| 来源 | 性质 | 示例 |
|------|------|------|
| LLM 调用失败 | 事件 | 单次调用的 HTTP 错误 / 超时 |
| LLM 初始化失败 | 状态 | active provider 配置损坏（无 key / 空 base_url） |
| 消息入队失败 | 事件 | queue 满 |
| key 写入失败 | 事件 | env 文件不可写 |
| core 不可达 | 状态 | 后端离线 |

`unconfigured` / `debug` 不算错误——它们有自己的引导流。

## 展示层

三个出口，各答一个问题：

- **气泡**（chat 流）——"这一轮发生了什么"；事件驱动，一次一报。
- **banner**（chat 顶部）——"系统需要你处理"；状态驱动，指向引导的常驻入口。
- **错误帧 Card**（pet 侧）——降级状态的常驻存在；与气泡的一次性互补。

## 通道

来源的性质决定它的通道：

- **事件**以 `llm_error` 式 effect 流动（每轮取走即清）→ **气泡**。
- **状态**独立于事件被检测 → **banner / Card**。

走错通道即坏：持久状态当一次性事件报 → 首次后永久静默；事件每轮重报 → 刷屏。
