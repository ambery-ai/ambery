# i18n Design

English | [中文](i18n.zh.md)

## Scope

i18n handles human-readable text produced by the application itself and subsequently by Harness; it does not translate machine contracts, nor does it rewrite user or LLM content that has already been produced.

## Two Independent Global Language Preferences

Config provides two global fields that can be switched directly in the settings panel:

```text
ui_language       UI 自身文案的语言
harness_language  Harness 内部人类可读文本的语言
```

The two are chosen independently; they do not auto-switch by project, terminal instance, Chat conversation, or individual user message.

```text
UI = English，Harness = 中文  合法
UI = 中文，Harness = English  合法
```

An explicit user choice for either field always wins; the system language is not re-applied over it after the user has chosen.

## UI Language

The UI language controls the application's built-in copy, such as settings, buttons, the Chat placeholder, status notices, and error descriptions.

- After switching, the UI copy is re-rendered immediately.
- It does not translate or rewrite user messages, user-given names, existing Chat history, existing Card content, or already generated LLM output.
- On first launch, the UI language follows a supported system language; if the system language is unsupported, it falls back to the project's explicit UI default language.

## Harness Internal Language

The Harness language controls human-readable text subsequently used for system–LLM collaboration, such as the default identity prompt, system event text, tool descriptions, parameter descriptions, error feedback, and default prompt copy.

- A switch takes effect starting from the next new LLM interaction; it does not rewrite existing Context, Chat history, or already generated content.
- The Harness language is a global, explicit, stable user preference; it is not guessed or flipped based on the current project or the language of user messages.
- On first launch, Harness uses the project's explicit default language and does not follow the system language; the user can later change it to another supported language in settings or Config.

Implementation notes (normative contract; the string table and lookup functions are in `core/src/i18n.rs`):

- Tool descriptions and parameter descriptions are looked up from the table each time an LLM request is built; system event text is written at the moment the event occurs (and thereafter becomes history that is not rewritten); tool execution errors are looked up at execution time.
- The persisted `base_prompt` and the two default AGENTS.md files (Config-domain identity / Memory workspace navigation) are generated in the Harness language at first launch, and are thereafter generated content; the AGENTS.md runtime fallback default is fetched in the current Harness language at the time of use.
- Audience-separation boundary: the validation copy of the unified modification pipeline is Config-domain mechanism output addressed to both the local user (settings panel) and the LLM, and it keeps the project default language rather than switching with the Harness language; error feedback on the tool execution path (execute_tool) follows the Harness language.
- Component interaction events (produced by the frontend): the frontend reports only structured facts (action + fields); the text is written by core through lifecycle as the single source in the Harness language at the time of use (user_action_desc) — the frontend does not assemble event text on its own.

## Stable Machine Contracts

Language switching translates only human-readable descriptions, never the contracts that machines must recognize stably:

```text
tool name
Config path
JSON key
协议字段
枚举值
```

For example, `edit_config`, `set_autonomy`, `kaomoji.system`, `action`, and `path` remain unchanged in any UI/Harness language.

The pet name is not translatable UI copy either. When Config is first initialized, the official default name `Ambery` is written (the default name is not differentiated by language); after that it becomes a stable, independent identity value, and switching the UI or Harness language does not automatically rename it. For naming rules, see `docs/view.md`.

## Support Scope and Public Notice

Chinese and English UI and Harness text are officially provided. English is a selectable, fully covered option maintained alongside releases, but README and Setup must clearly state: the English translation is generated by AI and may contain terminology, ambiguity, or wording errors; user feedback and correction contributions are welcome.

This notice belongs to language-selection and support documentation, and it should not persistently bother users in the normal UI or beside every piece of Harness text.
