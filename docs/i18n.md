# i18n 设计

## 范围

i18n 处理应用自身与 Harness 后续生成的、人类可读文本；它不翻译机器契约，也不改写已经产生的用户或 LLM 内容。

## 两个独立的全局语言偏好

Config 提供两个可在设置面板直接切换的全局字段：

```text
ui_language       UI 自身文案的语言
harness_language  Harness 内部人类可读文本的语言
```

两者独立选择，不按项目、terminal 实例、Chat 对话或单条用户消息自动切换。

```text
UI = English，Harness = 中文  合法
UI = 中文，Harness = English  合法
```

用户对任一字段的显式选择始终优先；系统语言不在用户已选择后重新覆盖它。

## UI 语言

UI 语言控制应用固有文案，例如设置、按钮、Chat placeholder、状态提示和错误说明。

- 切换后立即重渲染 UI 文案。
- 不翻译或改写用户消息、用户命名、既有 Chat 历史、既有卡片内容或已经生成的 LLM 输出。
- 首次启动时，UI 语言跟随受支持的系统语言；系统语言不受支持时回退到项目明确的 UI 默认语言。

## Harness 内部语言

Harness 语言控制后续供系统与 LLM 协作使用的人类可读文本，例如默认身份 prompt、系统事件文字、工具说明、参数说明、错误反馈与默认提示文案。

- 切换从下一次新的 LLM 交互开始生效；不改写已有 Context、历史 Chat 或已生成内容。
- Harness 语言是全局、显式且稳定的用户偏好；不根据当前项目或用户消息语言猜测和跳变。
- 首次启动时，Harness 使用项目明确的默认语言，不随系统语言自动改变；用户可随后在设置或 Config 中改为其他已支持语言。

实现注记（正文契约，字符串表与查表函数在 `core/src/i18n.rs`）：

- 工具说明与参数说明在每次 LLM 请求构建时现查表；系统事件文字在事件发生时刻现写（此后成为历史记录不被改写）；工具执行错误在执行时刻现查。
- 持久化的 `base_prompt` 与两份默认 AGENTS.md（Config 域身份 / Memory 工作空间导航）以首启时刻的 Harness 语言生成，此后属已生成内容；AGENTS.md 的运行时回退默认按当前 Harness 语言现取。
- 受众分离边界：统一修改管道的校验文案属 Config 域机制输出，同时面向本地用户（设置面板）与 LLM，保持项目默认语言不随 Harness 语言切换；tool 执行路径（execute_tool）的错误反馈跟随 Harness 语言。
- Component 交互事件（前端产生）：前端只上报结构化事实（action + 字段），文本由 core 经 lifecycle 单源按 Harness 语言现写（user_action_desc）——前端不各自拼事件文本。

## 稳定的机器契约

语言切换只翻译人读的说明，绝不翻译机器要稳定识别的契约：

```text
tool name
Config path
JSON key
协议字段
枚举值
```

例如 `edit_config`、`set_autonomy`、`kaomoji.system`、`action` 与 `path` 在任意 UI/Harness 语言下保持不变。

pet 名称也不是可翻译的 UI 文案。Config 首次初始化时写入正式默认名 `ペット`（不按语言区分默认名）；此后成为稳定独立的身份值，切换 UI 或 Harness 语言不自动改名。名称规则见 `docs/view.md`。

## 支持范围与公开说明

正式提供中文和英文的 UI 与 Harness 文本。英文是可选择、完整覆盖并随发布维护的选项，但 README 与 Setup 必须明确标注：英文翻译由 AI 生成，可能存在术语、歧义或措辞错误；欢迎用户反馈与贡献修正。

该标注属于语言选择与支持说明，不应在正常 UI 或每条 Harness 文本旁持续打扰用户。
