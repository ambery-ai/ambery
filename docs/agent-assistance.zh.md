## 原则

> **本文档范围**——本文定义 Agent Assistance 的最终工作协作能力目标；不定义能力计划、泛化任务、评估项目、覆盖或演进，见 `docs/capability-evaluation-project.md`；也不定义 Case Runner 基础设施，见 `docs/case-runner.md`。

## Agent Assistance

Agent 的根本角色是**工作监督与协作助手**：围绕用户正在进行的多线工作理解事实、管理注意力、推进协作。Config、终端、Context、Skill、可视化工具、跳转和 UI 都是达成这些目的的手段，不是能力分类本身。

**多线计划进度 Track**: 将多个并行计划作为持续的 Track 处理，维护每条线的目标、当前阶段、已确认进展、阻塞、下一步和关联上下文；跨终端实例、多个 turn 与中断持续掌握进度，不让用户在多条线之间丢失工作状态。

**工作态理解与注意力管理**: 理解当前正在发生的工作、终端变化、等待、完成、风险和需要决策的事项；过滤不值得打扰的噪音，在真正需要用户注意时及时说明原因、影响与下一步。

**协作式推进与回顾**: 协助用户理解现状、组织下一步、推进计划，并在用户追问或工作被中断后回顾“刚才发生什么”、恢复相关工作线与上下文；还应基于持续维护的 Track 形成日报、周记和项目阶段回顾，沉淀已确认进展、变化、阻塞与后续重点。

**模式自动化与快速回复**: 理解用户当前通过 Context Engineering 构建的内容及其作用，例如 Skill；在此基础上逐步提供快速回复自动化，帮助用户少打重复、低价值的字，同时不替用户作高风险决定，也不越过用户已建立的上下文、约束和工作方式。

**多工具理解与可视化呈现**: 理解现有多个工具的能力、边界与相互关系，并让这些可视化工具联系更紧密；在恰当时刻通过跳转、及时展示相关内容和组织上下文，帮助用户直接看到、进入和操作当前工作所需的信息，而不是只用文本描述。
