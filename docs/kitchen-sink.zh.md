# Kitchen Sink

[English](kitchen-sink.md) | 中文

> 它渲染的组件契约归 `docs/ui-composition.md`；主题取值归 `docs/theme.md`；Component 协议归 `docs/components.md`；行为验证归 `docs/case-runner.md`。

## 原则

> **本文范围** —— 本文定义渲染层的验证面：这个页面、它渲染什么、它有哪些控件，以及让它与产物保持同步的保证。它不定义组件契约、主题 value 字段，也不定义 Component 协议。

> **观测不动手** —— 这个面不接任何应用动作：不碰 IPC、不做窗口管理、不写存储、不接拖拽。一个能改状态的样张页是第二个入口，不是验证面。

> **不自带颜色** —— 本页不引入任何颜色：它画的每一个面都来自当前主题，主题选择是唯一的颜色输入。不是主题 token 的值就是缺陷，不是细节。

> **全部平铺** —— 任何选项都不许藏在控件背后：没有下拉、没有菜单、没有只在悬停时才出现的状态。每个选择一次把所有候选项摆出来，每个操作都设计成**点击一次即生效**。也不许有任何东西是悬浮的：没有钉在屏幕上的条、没有浮在内容之上的层、没有遮罩——一切都在文档流里。

> **这个面不持有副本** —— 它显示的一切都是产物代码与活数据：组件就是产物自己的组件，Card 经 Component 渲染器产出，token 取值从文档根现读，它枚举的清单来自产物自己的注册表。

## 覆盖面：case runner 留白的渲染层

`docs/case-runner.md` §Observation boundary 把渲染层排除在外——DOM 构造、CSS 与尺寸计算都不在它的观测范围内，投影后的 Card 尺寸只作为数据进入 case。kitchen sink 正是留给这一块的面：组件实际画出来的样子、token 表解析后的取值、以及一个表面可能处在的各个状态。

这两个面是互补的，不是重叠的。行为——回放、窗口决策、生命周期、信念状态——由 case runner 无头观测；外观——DOM、CSS、token、状态——在这里观测，而且在出货形态里观测。

## 版式

这一页是**一种读法的两段**：表面段在前（表面才是产物被评判的地方，规格段是它背后的材料），每段占满一屏。段比一屏长的那部分**在段内滚动**：屏幕上的段分界线只在过渡中被推上去，因此**静止时屏上永远只有一段**。右缘一列小点，既是当前位置指示，也是跳转入口。

```text
┌ 第一段 · 表面 ───────────────────────────────────────────── 正好一屏 ────┐
│ 主题 ▪▪▪▪▪▪▪▪▪        语言 [中][EN]                                       │
│  段内滚动：分界线停在屏顶                                                  │
│  面板按真实尺寸 + 各类型卡片                                               │
│                                                     段 ●○                 │
│            ↓ 滚到本段底部，再滚一格：整段被推上去、下一段顶上来            │
├ 分界线只在过渡中被推上去 ─────────────────────────────────────────────────┤
│ 主题 ▪▪▪▪▪▪▪▪▪        语言 [中][EN]                                       │
│  规格段内容（比一屏长时在段内继续滚）                                      │
│                                                     段 ○●                 │
└───────────────────────────────────────────────────────────────────────────┘
```

对整页生效的两项选择——主题与界面语言——是**一份页眉，在两段开头各渲染一次**。它**不常驻**：跟着段内内容一起滚过去，下一段开头再出现同一个页眉，于是控件待在"一段开始的地方"，既不跟着读者跑，也不压住内容、不离开文档流。两处读的是**同一份 model**，所以在任一处切换就是切整页。

分页器走的是同一套段间过渡动画，不另引第三方滑动库。

## 滚动

整页是一篇文档：页面高度就是内容高度，滚动条是产物自己的那条、在窗口右缘；每段一屏，段内内容自己滚。位移由浏览器原生滚动承担，本页只加一条"阅读可以停在哪儿"的规则。

**静止位置不跨段。** 每帧只问一件事——视口顶端与底端是不是落在同一段里？是就什么都不做（包括读者停在段中）；不是就朝**上一次滚动方向**滑到边界：往下滚 → 下一段起点对齐屏顶；往上滚 → 本段末尾对齐屏底。每个方向的落点唯一，所以两个方向各自收敛、不会互相顶；边线高度每帧现算，段多高、一次滚多远都成立。

```ts
// reading-scroll.ts —— 每帧一次
const MIN_MOVE = 2; // 小于这个距离就动手（避免为 1~2px 的舍入差反复触发）

const resetFor = (top: number, sections: HTMLElement[]): number | null => {
  const vh = viewH();
  const max = maxDoc();
  const sTop = sectionIndexOf(top, sections);
  const sBottom = sectionIndexOf(top + vh - 1, sections);
  if (sTop === sBottom) return null; // 同一段：不介入（含读者停在段中）
  const down = dir >= 0;
  const landing = down
    ? sBottom >= sections.length - 1
      ? max // 往下且已是最后一段：落到页面末
      : sections[sBottom].offsetTop // 往下：下一段起点对齐屏顶
    : sTop <= 0
      ? 0 // 往上且已在第一段：落到页面顶
      : sections[sTop].offsetTop + sections[sTop].offsetHeight - vh; // 往上：本段末尾对齐屏底
  const clamped = Math.max(0, Math.min(max, landing));
  return Math.abs(clamped - top) > MIN_MOVE ? clamped : null;
};
```

方向取自滚轮，或取自原生滚动（触屏、键盘）中位置的运动方向；掉头即取消进行中的复位、把位置交还读者。复位是定时的三次缓出，落点是**算出来的位置**而不是"逐渐逼近"，所以它精确停在边界上，不会差一两个像素。整套机制在 `reading-scroll.ts` 里，页面只负责挂上它。

滚动条外观不归本页管：它沿用应用的全局规则（细条 + 主题滑块色），所以在这里看到的滚动条就是产物画出来的那一条。

## 结构

```text
kitchen-sink.html ──► 样张入口 ──mount──► KitchenSink.svelte
                                            │
                          ┌─────────────────┴──────────────────┐
                          │                                    │
                       页眉                                    分页器
                       一份 model，每段一次                 两段 + 右侧小点
                          │                                    │
                          └────── 两者都只组合下面这些区块 ─────┘
                                            │
   ┌─────────────┬──────────────┬───────────┴──┬──────────────┬─────────────┐
TokenBoard   WidgetBoard     RowBoard      PanelBoard     CardWall
   │             │               │             │             │
真相源：       手写清单        手写样例      状态桩        真相源：
主题的         一级 widget     每种字段      面板收到的    Component
```

区块只负责渲染，别的什么都不做；每个区块在图上写明自己的真相源——这正是这一页无法漂移的原因。

## 扩展

| 新增什么 | 它怎么出现在页面上 | 谁在保证 |
|---|---|---|
| 一个 token | 自动 | token 板遍历主题的已知 token 表，而 token 守卫让这张表与 `:root` 表始终同步 |
| 一种 Component 类型 | 自动，而且先编译失败 | 样例表以 Component 类型联合为键，未表示的类型就是编译错误；卡片墙遍历样例表 |
| Component 内部的字段或组合形态 | 什么都不用做 | 样例是每类型一个实例，不是字段目录；组合形态就是再加一个样例 |
| 一个窗口面板 | 手写——面板块加一行，外加它需要的状态桩 | 覆盖面带出已渲染的面板清单 |
| 一个一级 widget | 手写——widget 块加一段 | 覆盖面把 widget 文件与页面声明的清单对比 |
| 一种读法（布局） | 手写——加一个文件、加一行清单 | — |
| 一套主题 | 自动 | 两处页眉枚举主题清单 |

新 Component 类型的传播链路：协议多一个类型 → 前端的类型联合多一个成员 → 类型检查随即拒绝通过，直到样例表里补上它的一个实例 → 卡片墙无需改动就把它显示出来。卡片墙不是手写的卡清单，而是对那张表的遍历，所以它永远不可能漏掉一个产物真能渲染的类型。

## 路由

样张页是前端包的一个 HTML 入口，两种形态都经该入口的路径进入：迭代时走 dev server，样式结论要在打包构建的 CSS 管线下成立时，用浏览器打开构建出来的样张页。应用入口不认识这一页——它的路由永远不会派发到样张页，Tauri 形态也没有为它声明窗口。

## 渲染内容

- 主题 token 表的每一个 token，并给出它在当前主题下解析到的取值。
- 一级 widget 的变体与状态——禁用、错误、只读。
- 二级组件配代表性数据：每种字段类型的配置行、三种状态的 provider key 行、按真实窗口尺寸摆放的面板。
- 每一种 Component 类型，经 Component 渲染器产出。

模态面**不在这里展示**：对话框、弹层与 Tooltip 天生是浮层，而这一页什么都不浮。模态里装什么，从它所基于的组件上判；承载它的壳负责它的行为。

状态与组件本身同属内容：只演顺路的页面并不展示这个面。空态、离线与只读降级、需重启横幅、错误行、超长标题、到达高度上限的 Card——每一个都是产物真实存在的渲染结果，都在这里判。

## 控件

- **主题与语言** —— 一份 model，在两段开头各渲染一次：两段都带着同样的控件，在任一处切换就是切整页。每一项都是**一行小框**而不是文字下拉：主题行画出当前在用那套的色板——底、面、文字、强调、状态色、气泡、图表——**显示的是配色本身，不是它的名字**；语言行把语言本身摆出来。今天只有内置那一套；第二套属于主题工作，本页不预设任何配色。页面上的每一句都是产物自己的 `t()` 输出，所以切语言是**换措辞**，不是翻译一份副本。

## 隔离

样张页不得进入应用产物：Tauri 壳嵌的就是那份产物，而验证面不是产品面——它的演示主题表与自己的样式表否则会随应用一起发出去。

隔离靠**入口**，不靠 dev 标志。应用入口与样张入口是同一个前端包里两个独立的 HTML 入口，样张构建写进自己的输出目录；两个入口互不引用，所以样张里的任何东西都拉不进应用产物，样张也不需要应用窗口世界的任何部分。

机制：Vite 的 `kitchen-sink` 档把构建指向样张入口、它自己的输出目录与相对路径 base，预览读同一档来服务那份产物——入口自启动，因此应用的路由表永远不认识这一页。

```text
npm run kitchen-sink:dev      → dev server；两个入口都在，样张在 /kitchen-sink.html
npm run kitchen-sink:build    → kitchen-sink.html 及其资产，写进 dist-kitchen-sink/
npm run kitchen-sink:preview  → 服务那份产物（读同一档，不再加别的开关）
```

dev 标志什么都隔离不了：它依赖同一条入口上的死代码消除，而一旦把这个标志打开——读打包构建下的样张恰恰需要打开它——样张的 chunk 与演示主题表就落进了应用产物。

样张页仍然回答那个问题：它自己的构建跑同一条 CSS 管线，所以用浏览器打开构建出来的样张页，就是在打包构建的管线下确认样式结论，而不必把这个页面塞进安装包。

两条断言让隔离名副其实：应用产物里搜不到样张的字符串或 chunk；样张产物里也不含应用的窗口入口。

## 同步保证

- 新 token 会自动出现在 token 清单里，因为那份清单就是主题的已知 token 表。
- 新的 Component 类型在样张页表示它之前会**编译失败**，因为样例表以 Component 类型联合为键——完整性由编译期强制，不靠人 review。
- 组件的变化无需改这个页面就会显现，因为页面组合组件，而不是复述组件。

## 不覆盖的部分

真实桌面行为：多屏与混合 DPI 下的落点、壳创建的窗口、托盘与系统级交互、负载下的开销。这些在真机的出货形态里读，不在这里。
